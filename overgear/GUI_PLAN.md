# OVERGEAR — แผน GUI ฉบับคร่าว ๆ

สถานะ: ร่างสำหรับคุยและปรับก่อนลงมือทำ GUI
ขอบเขตรอบนี้: วางหน้าจอและวิธีใช้งานเท่านั้น ยังไม่เขียน GUI และยังไม่สร้างรูปหรือ asset

## 1. เป้าหมายและข้อสมมติ

- เปลี่ยนเกมบริหารร้านตีอาวุธจากเมนู Terminal เป็นหน้าต่างที่เล่นด้วยเมาส์ได้ เห็นข้อมูลสำคัญโดยไม่ต้องเปิดเมนูหลายชั้น
- รักษาวงจรเดิม: รับงาน → ซื้อของ → ตีอาวุธ → ส่งงาน/จัดอาวุธให้ผู้กล้า → จบวัน → เตรียมรับมังกรวันที่ 30
- ใช้ Python + Tkinter/ttk ตามแนวทาง Bonus ใน PLAN.md และ README.md ไม่เพิ่ม dependency ในระยะแรก โดยเครื่องต้องมี Tkinter
- สมมติว่าเริ่มจาก Desktop บน Windows รองรับไทย/อังกฤษ และใช้เซฟ JSON เดิมร่วมกับ Terminal โดยเปิดเล่นทีละโปรแกรม
- ร่างนี้ยังไม่ถือเป็นการเลือกสไตล์ภาพขั้นสุดท้าย ขนาดหน้าต่างและการจัดวางปรับได้หลังลองใช้งานจริง

## 2. โครงหน้าต่างหลัก

ตั้งต้นประมาณ 1280 × 800 และปรับขนาดได้; ลองรองรับพื้นที่ใช้งาน 1024 × 720 ด้วยการเลื่อนรายการและย่อรายละเอียดรอง

```text
┌───────────────────────────────────────────────────────────────┐
│ OVERGEAR | วันที่ / วันมังกรบุก | ทอง | ชื่อเสียง | ภาษา        │
├──────────────┬──────────────────────────────┬───────────────────┤
│ หน้าร้าน     │ พื้นที่หน้าที่กำลังเปิด       │ รายละเอียดรายการ  │
│ ออเดอร์      │                              │ ที่เลือก / ผลลัพธ์  │
│ ตลาด         │ ข่าว / รายการ / โต๊ะตีอาวุธ  │ / ปุ่มดำเนินการ    │
│ เตาหลอม      │                              │                   │
│ ชั้นวาง      │                              │                   │
│ ผู้กล้า      │                              │                   │
│ ลงทุน        │                              │                   │
│ บันทึกร้าน   │                              │                   │
├──────────────┴──────────────────────────────┴───────────────────┤
│ ตีได้อีกกี่ครั้ง | คลัง / ชั้นวาง | ข้อความล่าสุด | จบวัน       │
```

แถบบนและปุ่มจบวันอยู่ตำแหน่งเดิมทุกหน้า รายละเอียดด้านขวาเปลี่ยนตามรายการที่เลือก; หน้าเตาหลอมใช้พื้นที่กลางและขวาร่วมกันได้ หากหน้าต่างแคบให้ย้ายรายละเอียดลงด้านล่าง

## 3. หน้าจอที่ต้องมี

| หน้า | ข้อมูลและการทำงานหลัก |
| --- | --- |
| หน้าแรก | เริ่มเล่น/เล่นต่อ, เริ่มใหม่และเลือกระดับความยาก, วิธีเล่น, ประวัติผลเกม, ภาษา, ออก |
| หน้าร้าน | ข่าววันนี้และข่าวลือพรุ่งนี้, งานใกล้ครบกำหนด, จำนวนครั้งตีที่เหลือ, เงินและค่าใช้จ่ายรายวัน, แชมป์และพลังป้องกันหมู่บ้าน |
| ออเดอร์ | แยกงานที่รอรับกับงานที่รับแล้ว; แสดงรางวัล สเปก วันส่ง และสิ่งที่ขาด; รับงาน, ดูสูตรแนะนำ, ไปตลาด/เตาหลอม, เลือกอาวุธส่ง, ซ่อม และยกเลิก |
| ตลาด | วัตถุดิบ ราคา แนวโน้ม จำนวนที่มี และพื้นที่คลัง; กำหนดจำนวนซื้อ/ขาย เห็นยอดรวมก่อนกด; แยกของที่ผู้กล้านำกลับมาขาย |
| เตาหลอม | เลือกแม่พิมพ์และส่วนประกอบ, แสดงวัตถุดิบที่ใช้และประมาณการเกรด; เริ่มตีด้วยตัวเองหรือตีอัตโนมัติ; แสดงผลและอาวุธที่ได้ |
| ชั้นวางอาวุธ | รายการอาวุธพร้อมเกรด ค่าสถานะ และชื่อสลัก; เลือกดูรายละเอียด, สลักชื่อ, ขาย, บริจาค และหลอมคืน |
| ผู้กล้า | ระดับ อาวุธ ภารกิจ พลังและความเสี่ยงคืนนี้; เลือกภารกิจ, มอบอาวุธ และตั้งแชมป์ |
| ลงทุน | อัปเกรดเตา, จ้าง/เลิกจ้างลูกมือ, ซื้อแม่พิมพ์ และขยายคลัง; แสดงราคา เงื่อนไข และผลที่จะได้ก่อนซื้อ |
| บันทึกร้าน | ประวัติรายวัน สถิติ และคาดการณ์เงินสด โดยใช้ข้อมูลที่เกมมีอยู่ |
| สรุปคืน/ฉากจบ | เหตุการณ์ ผู้กล้าที่กลับมา/เสียชีวิต ค่าใช้จ่าย และวันใหม่; วันที่ 30 แสดงผลสู้มังกรและกลับหน้าแรก |

## 4. จุดที่ควรออกแบบให้ใช้ง่ายเป็นพิเศษ

### ออเดอร์ → ตี → ส่ง

เลือกออเดอร์แล้วเห็นสเปกเทียบกับของที่มีทันที หากมีอาวุธพร้อมส่งให้เสนอชิ้นที่ตรงสเปก; หากยังไม่มีให้เปิดสูตรแนะนำและแสดงรายการของขาดก่อนพาไปตลาดหรือเตาหลอม การเปิดสูตรเป็นเพียงการเตรียมตัวเลือก ยังไม่ใช้วัตถุดิบจนกดเริ่มตี

### มินิเกมเตาหลอม

ใช้แถบความร้อนพร้อมตัวเลขและช่วงเหมาะสม แสดงความคืบหน้าและจำนวนจังหวะที่เหลือ มีปุ่มตาม action เดิม: ตีเบา / ตีแรง / รอ / สูบลม พร้อมผลของจังหวะล่าสุด

คงระบบผลัดจังหวะของเกมเดิม ไม่เปลี่ยนเป็นเกมจับเวลา แอนิเมชันในอนาคตเป็นเพียง feedback; ระยะแรกใช้แถบและข้อความได้ หากมีงานตีค้างตอนโหลดให้กลับมาตีต่อได้

### จบวัน

ก่อนยืนยันให้เห็นค่าใช้จ่าย งานที่กำลังจะหมดเวลา และแผนผู้กล้าคืนนี้ หากยังตีค้างให้แจ้งว่ากฎเดิมจะปิดงานให้อัตโนมัติ จากนั้นเรียกจบวันครั้งเดียว แสดงรายงานคืน แล้วเปิดวันใหม่หรือฉากจบ

## 5. แนวภาพเบื้องต้น — ยังไม่สร้างรูป

- เสนอธีมโรงตีเหล็กแฟนตาซี: พื้นถ่านเข้ม แผงสีน้ำตาลเหล็ก ตัวอักษรสีอ่อน ใช้สีทองแดง/ไฟเตาสำหรับปุ่มหลัก
- ให้ข้อมูลและปุ่มอ่านชัดก่อนตกแต่ง ใช้กรอบ เส้น และข้อความแทนรูปในต้นแบบ
- เกรดอาวุธใช้สีตามเกมเดิม แต่เขียนชื่อเกรดกำกับเสมอ ไม่ใช้สีเพียงอย่างเดียว
- ใช้ฟอนต์ระบบที่รองรับไทย; ทดสอบภาษาอังกฤษซึ่งอาจใช้ความกว้างต่างกัน และไม่พึ่ง emoji เป็นไอคอนหลัก
- เว้นพื้นที่ที่อาจใส่ภาพร้าน ผู้กล้า และอาวุธภายหลัง โดยยังไม่กำหนดชุดภาพหรือสั่งสร้าง asset

## 6. แนวทางเชื่อมกับโค้ดเดิม

- เพิ่มจุดเข้า GUI แยก เช่น `gui_main.py` และหน้าจอใน `gui.py` ก่อน แยกไฟล์ย่อยเมื่อเริ่มใหญ่จริง; `main.py` ยังเป็นทางเข้า Terminal
- อ่านสถานะปัจจุบันจาก `storage.state` และเรียกกฎเดิม เช่น `shop.do_accept`, `shop.do_deliver`, `market.do_buy`, `forge.do_start_forge`, `forge.do_strike`, `heroes.do_set_task` และ `day.do_end_day`
- ไม่เรียกเมนูที่มี `input()`/`print()` จาก GUI; ใช้ `language.get_text` และ `data.tr` สำหรับข้อความตามภาษาที่เลือก
- หลังทำรายการให้อัปเดตแถบสถานะ รายการ และรายละเอียดที่เกี่ยวข้อง โดยรักษารายการที่เลือกด้วย id เมื่อทำได้
- ตรวจชนิดค่าคืนของแต่ละฟังก์ชันจริงก่อนเชื่อม: บางตัวคืนข้อความผิดพลาด บางตัวคืน dictionary/ผลลัพธ์ ไม่ครอบทั้งหมดด้วยสมมติฐานเดียว
- ใช้พฤติกรรมบันทึกของกฎเดิม ตรวจผลสำเร็จของการเซฟเมื่อจำเป็น และรองรับการปิดหน้าต่างโดยไม่ทำงานตีค้างหาย

## 7. สถานะและข้อผิดพลาดที่ต้องเตรียม

- ไม่มีเซฟ, เซฟเสีย, ยังไม่มีออเดอร์/อาวุธ, ผู้กล้าเสียชีวิตหรือไม่มีแชมป์
- เงินไม่พอ, วัตถุดิบไม่ครบ, คลัง/ชั้นวางเต็ม, หมดจำนวนครั้งตี และแม่พิมพ์ยังไม่ปลดล็อก
- ปุ่มที่ยังทำไม่ได้แสดงเหตุผลใกล้ปุ่ม; หลังคลิกยังตรวจด้วยกฎเกมเดิมอีกครั้ง
- ยืนยันก่อนเริ่มเกมใหม่ ยกเลิกงาน หลอมอาวุธ และจบวัน พร้อมบอกผลกระทบที่เกี่ยวข้อง
- ป้องกันการกดซ้ำในรายการที่เปลี่ยนสถานะ โดยเฉพาะจบวันและส่งงาน
- ใช้คีย์บอร์ดเลือกและกดปุ่มได้ ข้อความผิดพลาดเป็นภาษาที่เลือก และเปลี่ยนภาษาแล้วปรับข้อความทั้งหน้าจอ

## 8. ลำดับลงมือในรอบถัดไป

1. **โครง GUI:** หน้าแรก หน้าร้าน การนำทาง ภาษา และโหลด/บันทึก ใช้ข้อความกับกล่องสีทั้งหมด
2. **วงจรเล่นหลัก:** ออเดอร์ ตลาด เตาหลอม ชั้นวาง และสรุปจบวัน ให้เล่นได้ต่อเนื่องก่อน
3. **ระบบที่เหลือ:** ผู้กล้า ลงทุน บันทึก คาดการณ์ และฉากจบ ให้ครอบคลุมความสามารถของ Terminal
4. **ตรวจการเล่น:** เล่นวงจรรับงานถึงส่งของ, โหลดงานตีค้าง, ลองข้อจำกัดทรัพยากร, สลับภาษา, ปรับขนาดหน้าต่าง และตรวจจบเกมวันที่ 30 ด้วยเซฟทดสอบแยก
5. **ค่อยตกลงภาพ:** หลัง layout และ flow ใช้งานได้ จึงเลือกสไตล์ภาพ รายการ asset และแอนิเมชันที่จะทำ

เกณฑ์ต้นแบบผ่าน: ผู้เล่นเริ่ม/เล่นต่อ รับงาน ซื้อของ ตี ส่งงาน และจบวันได้จาก GUI โดยไม่ใช้ Terminal, ตัวเลขตรงกับกฎเดิม และเปิดเซฟกลับมาเล่นต่อได้

## 9. เรื่องที่ยังเปิดไว้

- ต้องการหน้าตาเป็นเกมภาพประกอบเต็มฉาก หรือหน้าบริหารร้านที่เน้นข้อมูล
- ขนาดจอเป้าหมายจริง และจะเพิ่ม shortcut ใดหลังทดลองเล่น
- งานภาพและเสียงทั้งหมดรอเลือกแนวทางภายหลังตามคำสั่งผู้ใช้
