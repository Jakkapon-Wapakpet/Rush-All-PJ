# ⚔ DUNGEON RUSH

**เกม RPG จัดทีมฮีโร่ ซื้ออุปกรณ์ และพิชิตดันเจี้ยน 5 ชั้น**

ผู้เล่นมีทองจำกัด ต้องตัดสินใจว่าจะจ้างฮีโร่คนไหน ซื้ออาวุธหรือเกราะชิ้นไหน และให้ใครใส่อะไร ก่อนลงไปสู้กับมอนสเตอร์ มอนสเตอร์แต่ละชั้นมีจุดอ่อนและธาตุที่ตีไม่เข้าต่างกัน ข้อมูลทุกอย่างที่ผู้เล่นเพิ่ม แก้ไข หรือลบ (ฮีโร่ ไอเทม อุปกรณ์ที่สวมใส่) มีผลกับการต่อสู้ทันที เป้าหมายคือปราบ **มังกรดำ** ที่ชั้น 5

เกมรองรับภาษาไทยและอังกฤษ และบันทึกความคืบหน้าลงไฟล์ JSON อัตโนมัติ

---

## 🚀 วิธีรัน

ต้องใช้ **Python 3.6 ขึ้นไป** และไม่ต้องติดตั้ง package เพิ่ม (ใช้แค่ standard library: `os`, `json`, `copy`, `random`, `time`)

```bash
cd rush
python3 main.py
```

> **เริ่มเกมใหม่:** เลือกเมนู `8. เริ่มเกมใหม่` หรือลบไฟล์ `dungeon_rush_save.json`

### เวอร์ชันหน้าต่าง (GUI) — ส่วนเสริม
```bash
python3 gui.py
```
ใช้เซฟ กฎ และระบบต่อสู้ชุดเดียวกับเวอร์ชัน Terminal (เล่นต่อกันได้):
- **ซ้าย:** การ์ดฮีโร่ (HP/XP ค่าพลัง ธาตุ อุปกรณ์) ปุ่มเปลี่ยนชื่อ ✎ ไล่ออก ✕ ถอดอุปกรณ์ ช่องรับสมัครฮีโร่ และโรงเตี๊ยม
- **ดันเจี้ยน:** แผนที่ 5 ชั้น ข้อมูลศัตรู การจับคู่ธาตุกับทีม โอกาสชนะ และภาพการต่อสู้ทีละเทิร์นพร้อมแถบ HP
- **ร้านค้า:** กรอง/เรียงสินค้า ปุ่มซื้อ และอันดับของคุ้มที่สุด
- **กระเป๋า:** ใส่ไอเทมให้ฮีโร่ด้วยปุ่มชื่อฮีโร่ และขายของ
- **บันทึก:** ความคืบหน้า สถิติ และฮีโร่เด่น

> ต้องมี Tkinter (บน Ubuntu ติดตั้งด้วย `sudo apt install python3-tk`) ถ้าไม่มี `gui.py` จะแจ้งให้ใช้ `python3 main.py` แทน

## 🎮 วิธีเล่น

```
====================================================
            ⚔  D U N G E O N   R U S H  ⚔
====================================================
 ทอง 120  |  ชั้น 1/5  |  ทีม 1/3  |  กระเป๋า 0/10
----------------------------------------------------
1. ทีมฮีโร่            ← รับสมัคร / ดู / เปลี่ยนชื่อ / ไล่ออก
2. ร้านค้า             ← ดูสินค้า (กรอง/เรียง) / ซื้อ / ขาย / ของคุ้มที่สุด
3. กระเป๋า / สวมใส่     ← ดูกระเป๋า / สวมใส่ / ถอด
4. ลงดันเจี้ยน          ← เลือกชั้น → สอดแนม → ต่อสู้
5. โรงเตี๊ยม            ← จ่ายทองเพื่อฟื้น HP
6. บันทึกการผจญภัย      ← สถิติ
7. เปลี่ยนภาษา   8. เริ่มเกมใหม่   0. ออกจากเกม
```

1. เริ่มเกมด้วยทอง 120 และนักรบ 1 คน (Arthur)
2. **เตรียมตัวในเมือง:** จ้างฮีโร่ (สูงสุด 3 คน) ซื้ออุปกรณ์ แล้วให้ฮีโร่สวมใส่
3. **ลงดันเจี้ยน:** ก่อนสู้ เกมจะแสดงข้อมูลศัตรู จุดอ่อน ธาตุที่ตีไม่เข้า และ **โอกาสชนะ** ที่คำนวณจากทีมปัจจุบัน
4. **ต่อสู้อัตโนมัติ** แสดงผลทีละเทิร์น ถ้าชนะจะได้ทองและ XP แล้วปลดล็อกชั้นถัดไป ถ้าแพ้จะเสียทอง 20%
5. ชั้นที่ผ่านแล้วกลับไปสู้ซ้ำได้ (ฝึก) โดยได้ทองครึ่งเดียว ใช้หาทองและเลเวลเพิ่ม

### อาชีพฮีโร่

| อาชีพ | ค่าจ้าง | HP | ATK | DEF | จุดเด่น |
| :--- | ---: | ---: | ---: | ---: | :--- |
| นักรบ | 50 | 45 | 8 | 5 | HP และพลังป้องกันสูง |
| นักเวท | 60 | 26 | 11 | 2 | โจมตีแรงแต่ตัวบาง |
| นักธนู | 55 | 32 | 9 | 3 | สมดุลทุกด้าน |
| นักบวช | 55 | 34 | 5 | 4 | รักษาเพื่อนที่ HP ต่ำสุดทุกเทิร์น |

### สูตรต่อสู้

> **ดาเมจ = ATK ของผู้โจมตี − DEF ของผู้รับ** (อย่างน้อย 1, สุ่ม ±20%)
> ถ้าเป็นธาตุที่ศัตรูแพ้ทาง → **x2** ถ้าเป็นธาตุที่ศัตรูตีไม่เข้า → **0**

- ATK/DEF ของฮีโร่ = ค่าของฮีโร่ + ค่าของอาวุธ/เกราะที่ใส่ และธาตุการโจมตีขึ้นกับอาวุธ
- ฮีโร่ดื่มยาในกระเป๋าอัตโนมัติเมื่อ HP ต่ำกว่า 40%
- มอนสเตอร์โจมตีฮีโร่แบบสุ่ม ตัวที่อยู่ชั้นลึกโจมตี 2 ครั้งต่อเทิร์น

## ✅ เกณฑ์ Rush00 ทั้ง 8 ข้อ

### 1. Interactive Menu and User Input
เมนูหลักมี 8 ตัวเลือก (ไม่รวมออกจากเกม) และมีเมนูย่อยในทีมฮีโร่ ร้านค้า และกระเป๋า ใช้ `input()` รับคำสั่ง ใช้ `print()` แสดงผล และวนรับคำสั่งจนกว่าผู้เล่นจะเลือก `0`

### 2. Data Structures and Data Management
- **list:** `heroes` (ทีม), `bag` (กระเป๋า), `MONSTERS` (มอนสเตอร์ 5 ชั้น)
- **dict:** ฮีโร่แต่ละคน (`{"name", "class", "level", "hp", "atk", "def", "weapon", "armor", ...}`), ไอเทม, อาชีพ, มอนสเตอร์, สถานะเกม (`storage.state`) และตารางเมนู (`actions = {"1": view_party, ...}`)
- **เพิ่ม / ดู / แก้ไข / ลบ:**
  - ฮีโร่: รับสมัคร / ดูทีม / เปลี่ยนชื่อ และเลเวลอัป / ไล่ออก
  - ไอเทม: ซื้อ / ดูกระเป๋า / สวมใส่และถอด / ขาย
- ข้อมูลอยู่ตลอดการเล่น และบันทึกลง JSON ทุกครั้งที่เปลี่ยน

### 3. Conditional Logic — กฎที่เปลี่ยนผลลัพธ์
| กฎ | อยู่ที่ |
| :--- | :--- |
| **ทองไม่พอ** → ซื้อของ / จ้างฮีโร่ / พักโรงเตี๊ยมไม่ได้ | `storage.check_gold` (ใช้ใน `do_buy`, `do_recruit`, `do_rest`) |
| **กระเป๋าเต็ม** (10 ช่อง) → ซื้อเพิ่มไม่ได้ | `items.do_buy` |
| **อาชีพไม่ตรง / เลเวลไม่ถึง** → สวมใส่ไม่ได้ | `items.check_can_equip` |
| **ทีมเต็ม** (3 คน) → จ้างเพิ่มไม่ได้ และ **ไล่คนสุดท้ายออกไม่ได้** | `heroes.check_party_space`, `heroes.check_can_dismiss` |
| **ขายของที่มีคนใส่อยู่ไม่ได้** และไอเทม 1 ชิ้นใส่ได้ทีละคน | `items.do_sell`, `items.do_equip` |
| **ชื่อฮีโร่ห้ามว่าง ห้ามซ้ำ และยาวไม่เกิน 12 ตัวอักษร** | `heroes.validate_hero_name` |
| **ธาตุที่แพ้ทาง x2 / ธาตุที่ตีไม่เข้า = 0** | `dungeon.hit_monster` |

### 4. Loops and Iteration
- **while:** เมนูหลัก, เมนูย่อยทุกเมนู, การเลเวลอัป (ขึ้นหลายเลเวลในครั้งเดียวได้)
- **for:** เทิร์นการต่อสู้, ตาของฮีโร่แต่ละคน, แสดงรายการ, กรอง/เรียงสินค้า, รวมค่าพลัง, จำลองการต่อสู้หลายร้อยครั้ง
- ทุกลูปมีทางออกชัดเจน (`return` / `break`) และการต่อสู้จำกัดไว้ไม่เกิน 30 เทิร์น

### 5. Functions and Program Organization
แบ่งเป็น 9 โมดูล (ไม่นับ GUI) มีฟังก์ชัน 83 ตัว ตัวอย่าง:
- **รับ parameter:** `shop_items(type_filter, sort_by, affordable_only)`, `fight(monster, rng, show)`, `gain_xp(hero, amount)`, `check_can_equip(hero, key)`, `choose_from_list(items, prompt_th, prompt_en)`
- **คืนค่าด้วย return:** `hero_attack` → ATK รวม, `party_power` → dict พลังรวม, `win_chance` → % โอกาสชนะ, `best_value_items` → อันดับไอเทม, `validate_hero_name` → ข้อความผิดพลาดหรือ `""`, `fight` → ผลการต่อสู้

### 6. Algorithm and Data Processing
| การประมวลผล | อยู่ที่ |
| :--- | :--- |
| **กรองและเรียงสินค้า** ตามประเภท ราคา ค่าพลัง เลเวล และเฉพาะของที่ซื้อไหว | `items.shop_items` |
| **จัดอันดับของคุ้มที่สุด** (ค่าพลังต่อ 100 ทอง) | `items.best_value_items` |
| **รวมค่าพลังของทีม** (HP / ATK / DEF รวมอุปกรณ์) | `heroes.party_power` |
| **คำนวณโอกาสชนะ** ด้วยการจำลองการต่อสู้ 300 ครั้ง (Monte Carlo) | `dungeon.win_chance` |
| **สถิติ:** อัตราชนะ ทองที่หาได้/ใช้ไป และหาฮีโร่ที่โจมตีแรงที่สุด/อึดที่สุด/เลเวลสูงสุด (ค่าสูงสุด) | `dungeon.adventure_stats` |

### 7. Input Validation and Error Handling
- เลือกเมนูที่ไม่มี → "ไม่มีเมนูนี้" แล้วกลับมาให้เลือกใหม่
- พิมพ์ตัวอักษรแทนตัวเลข → ดักด้วย `try/except ValueError` แจ้ง "กรุณากรอกเป็นตัวเลข"
- เลขเกินช่วงหรือติดลบ → "ไม่มีหมายเลขนี้" และพิมพ์ `0` เพื่อยกเลิกได้ทุกที่
- ทำกับข้อมูลที่ไม่มีอยู่ (ถอดช่องที่ว่าง, ขายเมื่อกระเป๋าว่าง, สวมใส่เมื่อไม่มีอุปกรณ์) → แจ้งเหตุผล
- ไฟล์เซฟหายหรือเสีย → เริ่มเกมใหม่แทน
- Ctrl+C / Ctrl+D → บันทึกแล้วออกโดยไม่ crash

### 8. Functional Application
ตัวอย่างการเล่นตั้งแต่ต้นจนจบ:
1. ลงชั้น 1 ชนะสไลม์ → ได้ 60 ทอง
2. ซื้อดาบเหล็ก → ให้ Arthur ใส่ → ATK เพิ่มจาก 8 เป็น 14
3. จ้างนักบวช → ชนะชั้น 2 → ทั้งทีมเลเวลอัป
4. สอดแนมชั้น 3 → วิญญาณหลอนตีด้วยอาวุธกายภาพไม่เข้า → **โอกาสชนะ 0%**
5. ซื้อคทาศักดิ์สิทธิ์ให้นักบวช → โอกาสชนะเพิ่มขึ้น → ชนะ
6. บันทึกการผจญภัยแสดงสถิติที่เปลี่ยนไป และออกจากเกมแล้วเปิดใหม่ ข้อมูลยังอยู่
