# 🧪 WITCH'S BREW — ร้านยาแม่มด

**แอปจัดการร้านยาแม่มด: ซื้อสมุนไพร ปรุงยา ค้นพบสูตรลับ และรักษาชาวบ้าน**

ผู้ใช้เป็นแม่มดที่เปิดร้านยาในหมู่บ้าน แต่ละวันต้องซื้อสมุนไพรจากตลาด (ราคาขึ้นลงทุกวัน) ปรุงยาตามสูตร ตั้งราคา แล้วขายให้ชาวบ้านที่มาพร้อมอาการป่วยและงบประมาณที่ต่างกัน ระหว่างทางยังค้นพบ **สูตรลับ** ใหม่ได้จากการลองผสมสมุนไพร แต่ถ้าผสมของที่เข้ากันไม่ได้ หม้อจะ **ระเบิด!**

แอปรองรับภาษาไทยและอังกฤษ และบันทึกข้อมูลลงไฟล์ JSON อัตโนมัติ

---

## 🚀 วิธีรัน

ต้องใช้ **Python 3.6 ขึ้นไป** และไม่ต้องติดตั้ง package เพิ่ม (ใช้แค่ standard library: `os`, `json`, `copy`, `random`)

```bash
cd rush
python3 main.py
```

> **เริ่มร้านใหม่:** เลือกเมนู `9. เริ่มร้านใหม่` หรือลบไฟล์ `witch_brew_save.json`

## 🎮 วิธีใช้งาน

```
========================================================
              🧪  W I T C H ' S   B R E W  🧪
========================================================
 วันที่ 1  |  ทอง 100  |  ชื่อเสียง ★★★☆☆  |  ตำรา 3/7
--------------------------------------------------------
1. ตลาดสมุนไพร           ← ดูราคาวันนี้ / ซื้อ / ทิ้ง
2. หม้อปรุงยา             ← ปรุงยา / ตอนนี้ปรุงอะไรได้บ้าง
3. ชั้นวางยา (1/10)       ← ดูยา / ตั้งราคา / ทิ้งยา
4. หน้าร้าน (ลูกค้ารอ 3 คน) ← ดูอาการ ดูยาที่แนะนำ แล้วขาย
5. ตำรายา                ← สูตรที่รู้ + คำใบ้สูตรลับ
6. บัญชีร้าน              ← สถิติ
7. ปิดร้าน → วันถัดไป
8. เปลี่ยนภาษา   9. เริ่มร้านใหม่   0. ออก
```

**วงจร 1 วัน:**
1. 🌅 **ตลาด:** ซื้อสมุนไพร ราคาเปลี่ยนทุกวัน และมีของลดราคาให้เลือก
2. 🔮 **หม้อปรุงยา:** เลือกสมุนไพร 2–3 อย่างใส่หม้อ
   - ตรงสูตรที่รู้แล้ว → ได้ยาวางบนชั้น
   - ตรงสูตรลับ → ✨ **ค้นพบสูตรใหม่!** บันทึกลงตำรา
   - ไม่ตรงสูตรไหน → ยาเสีย เสียสมุนไพรไปฟรีๆ
   - ผสมของต้องห้าม → 💥 **หม้อระเบิด** เสียค่าซ่อม
3. 🧑‍🌾 **หน้าร้าน:** ลูกค้ามาพร้อมอาการ 1–2 อย่างและงบที่มี แอปแนะนำยาที่ช่วยได้ ถ้าขายยาที่รักษาครบทุกอาการในราคาไม่เกินงบ ลูกค้าจะซื้อ
4. 🌙 **ปิดร้าน:** สรุปรายได้ของวัน แล้วเริ่มวันใหม่พร้อมลูกค้าใหม่และราคาตลาดใหม่

**ชื่อเสียง:** ขายสำเร็จ +3, ให้ยาผิดอาการ −5, ส่งลูกค้ากลับ −2 ร้านที่ชื่อเสียงดีจะมีลูกค้าที่มีงบสูงขึ้น

## ✅ เกณฑ์ Rush00 ทั้ง 8 ข้อ

### 1. Interactive Menu and User Input
เมนูหลักมี 9 ตัวเลือก (ไม่รวมออก) มีเมนูย่อยในตลาด หม้อปรุงยา ชั้นวางยา และหน้าร้าน ใช้ `input()` รับคำสั่ง ใช้ `print()` แสดงผล และวนรับคำสั่งจนกว่าผู้ใช้จะเลือก `0`

### 2. Data Structures and Data Management
- **list:** ลูกค้าที่รออยู่ (`customers`), สูตรที่รู้แล้ว (`known`), สมุนไพรในแต่ละสูตร, สรุปรายวัน (`daily`)
- **dict:** คลังสมุนไพร (`{"mint": 3, ...}`), ชั้นวางยา (`{"cough_syrup": 2}`), ราคาที่ตั้งเอง, ลูกค้าแต่ละคน (`{"name", "symptoms", "budget"}`), สูตรยาแต่ละสูตร และตารางเมนู
- **เพิ่ม / ดู / แก้ไข / ลบ:**
  - สมุนไพร: ซื้อ / ดูคลัง / ทิ้ง
  - ยา: ปรุง / ดูชั้น / ตั้งราคา / ขายหรือทิ้ง
  - ตำรา: เพิ่มสูตรเมื่อค้นพบ
- ข้อมูลอยู่ตลอดการใช้งาน และบันทึกลง JSON ทุกครั้งที่เปลี่ยน

### 3. Conditional Logic — กฎที่เปลี่ยนผลลัพธ์
| กฎ | อยู่ที่ |
| :--- | :--- |
| **ทองไม่พอ** → ซื้อสมุนไพรไม่ได้ | `storage.check_gold` ใน `market.do_buy_herb` |
| **สมุนไพรไม่พอ / ต้องใช้ 2–3 อย่างที่ไม่ซ้ำกัน** → ปรุงไม่ได้ | `brewing.do_brew` |
| **ผสมของต้องห้าม** → 💥 หม้อระเบิด เสียสมุนไพรและค่าซ่อม | `brewing.forbidden_pair`, `brewing.do_brew` |
| **ชั้นวางเต็ม** (10 ขวด) → ปรุงเพิ่มไม่ได้ | `brewing.do_brew` |
| **ยาไม่ตรงอาการ** → ลูกค้าไม่จ่าย และชื่อเสียง −5 | `shop.do_serve` |
| **ราคาเกินงบลูกค้า** → ลูกค้าไม่ซื้อ | `shop.do_serve` |
| **ราคาต้องอยู่ระหว่าง 1–999** และเตือนถ้าตั้งต่ำกว่าต้นทุน | `shop.do_set_price`, `shop.set_price` |

### 4. Loops and Iteration
- **while:** เมนูหลัก, เมนูย่อยทุกเมนู, หน้าร้าน (วนดูแลลูกค้าจนหมด), การสุ่มอาการไม่ให้ซ้ำ
- **for:** ไล่ตรวจทุกสูตรเทียบกับคลัง, ตรวจคู่ต้องห้าม, คำนวณต้นทุน, สุ่มราคาตลาด, แสดงรายการ, รวมสถิติ
- ทุกลูปมีทางออกชัดเจน (`return` / `break`)

### 5. Functions and Program Organization
แบ่งเป็น 9 โมดูล มีฟังก์ชัน 70 กว่าตัว ตัวอย่าง:
- **รับ parameter:** `do_brew(herbs)`, `do_serve(customer, recipes)`, `do_buy_herb(key, amount)`, `coverage(recipes, symptoms)`, `choose_many(items, prompt_th, prompt_en, most)`
- **คืนค่าด้วย return:** `find_recipe` → สูตรหรือ `None`, `brewable_now` → รายการสูตรที่ปรุงได้, `recommend` → ยาที่แนะนำ, `recipe_cost` → ต้นทุน, `shop_report` → dict สถิติ, `do_brew` → ผลการปรุง

### 6. Algorithm and Data Processing
| การประมวลผล | อยู่ที่ |
| :--- | :--- |
| **ตอนนี้ปรุงอะไรได้บ้าง:** ไล่ทุกสูตรที่รู้ คำนวณว่าปรุงได้กี่ขวดจากคลัง (ค่าน้อยสุดของสมุนไพรที่ใช้) แล้วเรียงจากมากไปน้อย | `brewing.brewable_now` |
| **แนะนำยาตามอาการ:** ให้คะแนนว่ายาแต่ละขวดรักษาอาการลูกค้าได้กี่ % แล้วเรียงจากรักษาได้มากสุดและราคาถูกสุด | `shop.recommend`, `shop.coverage` |
| **จับคู่สูตร:** เทียบชุดสมุนไพรกับทุกสูตรโดยไม่สนลำดับ | `brewing.find_recipe` |
| **ต้นทุนและกำไรต่อขวด** ตามราคาตลาดวันนี้ และ **หาของถูกวันนี้** (เรียงตาม % ที่ลด) | `brewing.recipe_cost`, `market.bargains` |
| **สถิติ:** กำไรสุทธิ รายได้เฉลี่ยต่อวัน วันที่ขายดีที่สุด ยาขายดีที่สุด (ค่าสูงสุด) และอัตราการขายสำเร็จ | `shop.shop_report` |

### 7. Input Validation and Error Handling
- เลือกเมนูที่ไม่มี → "ไม่มีเมนูนี้" แล้วกลับมาให้เลือกใหม่
- พิมพ์ตัวอักษรแทนตัวเลข → ดักด้วย `try/except ValueError` แจ้ง "กรุณากรอกเป็นตัวเลข"
- จำนวนหรือราคานอกช่วง (เช่น `0`, `-5`, `5000`) → แจ้งช่วงที่ถูกต้อง
- เลือกหลายรายการแบบผิด (เช่น `1,1`, `1,x`, `9`) → แจ้งว่าซ้ำ / ไม่ใช่ตัวเลข / ไม่อยู่ในรายการ
- ทำกับของที่ไม่มี (ทิ้งสมุนไพรเกินที่มี, ขายยาที่ไม่มีบนชั้น) → แจ้งเหตุผล
- ไฟล์เซฟหายหรือเสีย → เริ่มร้านใหม่แทน
- Ctrl+C / Ctrl+D → บันทึกแล้วออกโดยไม่ crash

### 8. Functional Application
ตัวอย่างการใช้งานตั้งแต่ต้นจนจบ:
1. ไปตลาด ซื้อสะระแหน่ (ลองซื้อขนนกฟีนิกซ์ 20 ชิ้น → **ทองไม่พอ**)
2. ปรุง สะระแหน่ + น้ำผึ้ง → ได้ **ยาแก้ไอ**
3. ลอง ขิง + สะระแหน่ + น้ำผึ้ง → ✨ **ค้นพบสูตรลับ: ยาครอบจักรวาล**
4. ลอง รากมังกร + ดอกจันทร์ → 💥 **หม้อระเบิด!**
5. ลูกค้ามีอาการ "ไอ + ตัวร้อน" → แอปแนะนำยาครอบจักรวาล (รักษาได้ 100%) → ขายสำเร็จ
6. ปิดร้าน → ดูบัญชีร้าน: รายได้ กำไร ยาขายดี และความคืบหน้าของตำรา
