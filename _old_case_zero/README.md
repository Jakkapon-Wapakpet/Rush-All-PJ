# CASE ZERO 🕵
**เกมสืบสวนคดีปริศนา / Mystery Investigation Game**

CASE ZERO คือเกมนักสืบบน Terminal ที่เขียนด้วย Python ผู้เล่นรับบทนักสืบ อ่านแฟ้มคดี เทียบหลักฐานกับคำให้การของผู้ต้องสงสัย แล้วชี้ตัวคนร้ายพร้อมหลักฐานที่พิสูจน์ว่าเขาโกหก

นอกจากตัวเกม ยังมีระบบจัดการแฟ้มคดีและหลักฐาน (เพิ่ม ดู ค้นหา แก้ไข ลบ) และรายงานสถิติการสืบสวน รองรับภาษาไทยและอังกฤษ และบันทึกข้อมูลลงไฟล์ JSON อัตโนมัติ

---

## 🚀 วิธีรันโปรแกรม

ต้องใช้ **Python 3.6 ขึ้นไป** และไม่ต้องติดตั้ง package เพิ่ม (ใช้แค่ standard library: `os`, `json`, `copy`)

```bash
cd rush
python3 main.py
```

เมื่อเปิดโปรแกรม ให้เลือกภาษา (1 = ไทย, 2 = English) แล้วจะเข้าสู่เมนูหลัก

### เวอร์ชันหน้าต่าง (GUI) — ส่วนเสริม
```bash
python3 gui.py
```
หน้าต่างมี 3 แท็บ ใช้ข้อมูลและกฎชุดเดียวกับเวอร์ชัน Terminal:
- **สืบสวน:** กระดานสืบสวนที่มีการ์ดสรุปคดี การ์ดหลักฐาน และการ์ดผู้ต้องสงสัยพร้อมคำให้การ คลิกการ์ดผู้ต้องสงสัยและการ์ดหลักฐานเพื่อเลือก แล้วกด "ชี้ตัวคนร้าย"
- **แฟ้มคดี:** ตารางคดีที่ค้นหา กรองตามสถานะ/ระดับ และเรียงลำดับได้ พร้อมฟอร์มเพิ่ม แก้ไข เปลี่ยนสถานะ ลบคดี และเพิ่มหลักฐาน
- **รายงาน:** การ์ดตัวเลข อัตราปิดคดี และกราฟแท่งตามสถานะและระดับความยาก

> ต้องมี Tkinter (บน Ubuntu ติดตั้งด้วย `sudo apt install python3-tk`) ถ้าไม่มี `gui.py` จะแจ้งให้ใช้ `python3 main.py` แทน

> **เริ่มเกมใหม่ทั้งหมด:** ลบไฟล์ `case_zero_data.json` แล้วรันโปรแกรมอีกครั้ง โปรแกรมจะโหลดคดีเริ่มต้นกลับมาให้

## 🎮 วิธีเล่น

```
============================================
              CASE ZERO
============================================
1. 🕵  เริ่มสืบสวนคดี
2. แฟ้มคดี (ดู/เพิ่ม/ค้นหา/แก้ไข/ลบ)
3. ห้องเก็บหลักฐาน
4. รายงานการสืบสวน
5. เปลี่ยนภาษา
0. ออกจากระบบ
```

1. เลือก **1. เริ่มสืบสวนคดี** แล้วเลือกคดีที่ยังเปิดอยู่
2. หน้าแฟ้มคดีจะแสดง **รายละเอียดคดี หลักฐานทุกชิ้น และคำให้การของผู้ต้องสงสัยทุกคน** ในหน้าเดียว
3. วิเคราะห์ว่าคำให้การของใครขัดกับหลักฐาน (มีหลักฐานหลอกปนอยู่ด้วย!)
4. เลือก **ชี้ตัวคนร้าย** → เลือกผู้ต้องสงสัย → เลือกหลักฐานที่พิสูจน์ว่าคนนั้นโกหก
5. ถูกทั้งคนและหลักฐาน → **ปิดคดี** และแสดงเฉลย
   ผิด → เสียโอกาส 1 ครั้ง ถ้าผิดครบ 3 ครั้ง คดีจะกลายเป็น **คดีค้าง**

คดีที่เล่นได้มี 2 คดี:

| รหัส | คดี | ระดับ |
| :--- | :--- | :--- |
| CASE-001 | ห้องปิดตาย (The Locked Room) | ปานกลาง |
| CASE-003 | ภาพวาดที่หายไป (The Missing Painting) | ยาก |

> ต้องการเล่นคดีที่ปิดหรือค้างไปแล้วอีกครั้ง: ไปที่ **แฟ้มคดี → อัปเดตสถานะคดี** แล้วเลือก "กำลังสืบสวน" ระบบจะล้างจำนวนครั้งที่ชี้ผิดให้

## 📋 ฟังก์ชันทั้งหมด

| เมนู | ทำอะไรได้ |
| :--- | :--- |
| **1. เริ่มสืบสวนคดี** | เล่นเกมสืบสวนตามขั้นตอนด้านบน |
| **2. แฟ้มคดี** | ดูคดีทั้งหมด, ดูรายละเอียดคดีพร้อมหลักฐาน, เพิ่มคดี, ค้นหาคดี, แก้ไขชื่อ/รายละเอียด/ระดับ, อัปเดตสถานะ, ลบคดี |
| **3. ห้องเก็บหลักฐาน** | ดูหลักฐานทั้งหมด, เพิ่มหลักฐานให้คดี (รหัส `EVD-xxx` สร้างอัตโนมัติ) |
| **4. รายงานการสืบสวน** | สถิติสรุปและอัตราปิดคดี, กรองคดีตามสถานะ, กรองคดีตามระดับความยาก, เรียงคดีตามรหัส/ชื่อ/ระดับ |

| **0. ออกจากระบบ** | บันทึกข้อมูลแล้วปิดโปรแกรม |

สถานะคดีมี 3 แบบ: **กำลังสืบสวน** (`open`), **ปิดคดีแล้ว** (`closed`), **คดีค้าง** (`cold`)

## ✅ เกณฑ์ Rush00 ทั้ง 8 ข้อ

### 1. Interactive Menu and User Input
เมนูหลักมี 5 ตัวเลือก (ไม่รวม Exit) และมีเมนูย่อยในแฟ้มคดี ห้องเก็บหลักฐาน และรายงาน ใช้ `input()` รับคำสั่ง ใช้ `print()` แสดงผล โปรแกรมวนรับคำสั่งจนกว่าผู้ใช้จะเลือก `0`

### 2. Data Structures and Data Management
- **list:** `all_cases` (คดีทั้งหมด), `all_evidence` (หลักฐานทั้งหมด), `"ผู้ต้องสงสัย"` (รายชื่อผู้ต้องสงสัยในแต่ละคดี)
- **dict:** คดี หลักฐาน และผู้ต้องสงสัยแต่ละรายการเป็น dict เช่น `{"รหัส": "CASE-001", "สถานะ": "open", ...}` และใช้ dict เป็นตารางเลือกเมนู (`actions = {"1": view_all_cases, ...}`)
- เพิ่ม ดู แก้ไข และลบได้ทั้งคดีและหลักฐาน ข้อมูลอยู่ตลอดการใช้งาน และบันทึกลง JSON

### 3. Conditional Logic — กฎที่เปลี่ยนผลลัพธ์
| กฎ | อยู่ที่ |
| :--- | :--- |
| **ชี้ตัวต้องถูกทั้งคนร้ายและหลักฐาน** ถึงจะปิดคดีได้ | `game.check_accusation` |
| **ชี้ผิดครบ 3 ครั้ง คดีกลายเป็นคดีค้าง** และเล่นต่อไม่ได้ | `game.check_accusation` |
| **รหัสคดีห้ามว่างและห้ามซ้ำ** | `cases.validate_case_id` |
| **หลักฐานต้องผูกกับคดีที่มีอยู่จริง** | `evidence.add_evidence`, `gui_manage.ManageView.on_add_evidence` |
| ข้อมูลสำคัญห้ามว่าง, ระดับความยากต้องเป็น ง่าย/ปานกลาง/ยาก | `cases.validate_case_fields` |
| ห้ามแก้ไข/ลบคดีที่ไม่มีอยู่จริง | `cases.edit_case`, `cases.delete_case`, `ManageView.on_save` |
| ลบคดีต้องยืนยันก่อน และหลักฐานของคดีนั้นจะถูกลบไปด้วย | `cases.delete_case` → `cases.remove_case` |

> กฎทุกข้ออยู่ในฟังก์ชันกลางที่ไม่มี `input()`/`print()` ทั้งเมนู Terminal และ GUI จึงเรียกใช้กฎชุดเดียวกัน

### 4. Loops and Iteration
- **while:** ลูปเมนูหลัก, เมนูย่อยทุกเมนู, ลูปหน้าแฟ้มคดีในเกม (ออกได้ทุกลูปด้วย `break` / `return`)
- **for:** วนแสดงคดี/หลักฐาน/ผู้ต้องสงสัย, ค้นหา, กรอง, นับสถิติ, หาเลขรหัสหลักฐานถัดไป

### 5. Functions and Program Organization
แบ่งเป็น 7 โมดูล (+ GUI อีก 3 โมดูล) มีฟังก์ชันมากกว่า 30 ตัว ตัวอย่าง:
- **รับ parameter:** `filter_cases(field, value)`, `sort_cases(sort_by)`, `choose_from_list(items, prompt_th, prompt_en)`, `find_case_by_id(case_id)`
- **คืนค่าด้วย return:** `find_case_by_id` → คดีหรือ `None`, `parse_difficulty` → ระดับหรือ `None`, `playable_cases` → list คดีที่เล่นได้, `check_accusation` → `"solved"`/`"wrong"`/`"cold"`, `validate_case_id` → ข้อความผิดพลาดหรือ `""`, `case_statistics` → dict สถิติ, `accuse_suspect` → `True`/`False` ว่าเกมจบหรือยัง

### 6. Algorithm and Data Processing
| การประมวลผล | อยู่ที่ |
| :--- | :--- |
| **ค้นหาคดี** แบบไม่สนตัวพิมพ์เล็ก/ใหญ่ ทั้งในรหัส ชื่อ และรายละเอียด (ทั้งสองภาษา) | `cases.match_cases` |
| **กรองคดี** ตามสถานะหรือระดับความยาก | `cases.filter_cases` |
| **เรียงคดี** ตามรหัส ชื่อ หรือระดับความยาก (ง่าย → ยาก) | `cases.sort_cases` |
| **สถิติ:** นับคดีแต่ละสถานะ/ระดับ และคำนวณอัตราปิดคดี (%) | `cases.case_statistics` |

### 7. Input Validation and Error Handling
- เลือกเมนูที่ไม่มี → แจ้ง "ไม่มีเมนูนี้" แล้วกลับมาให้เลือกใหม่
- พิมพ์ตัวอักษรแทนตัวเลขในเกม → ดักด้วย `try/except ValueError` แจ้ง "กรุณากรอกเป็นตัวเลข"
- เลขเกินหรือต่ำกว่าช่วงที่มี (เช่น `0`, `-1`, `99`) → แจ้ง "ไม่มีหมายเลขนี้"
- ค้นหา ดู แก้ไข หรือลบคดีที่ไม่มีอยู่ → แจ้ง "ไม่พบคดี"
- ไฟล์ JSON หายหรือเสีย → โหลดข้อมูลเริ่มต้นแทน
- กด Ctrl+C / Ctrl+D → บันทึกข้อมูลแล้วออกโดยไม่ crash

### 8. Functional Application
ตัวอย่างการใช้งานตั้งแต่ต้นจนจบ:
1. **รายงาน** → อัตราปิดคดีเริ่มต้น 33.3% (ปิดแล้ว 1 จาก 3 คดี)
2. **เริ่มสืบสวน** CASE-001 → ชี้ผิด 1 ครั้ง → ชี้ถูก → คดีปิด
3. **รายงาน** → อัตราปิดคดีเพิ่มเป็น 66.7%
4. **แฟ้มคดี** → เพิ่มคดีใหม่ → แก้ไข → ลบ
5. **ออกจากระบบ** แล้วเปิดใหม่ → ข้อมูลยังอยู่
